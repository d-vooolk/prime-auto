# Статьи и админка

Статьи раздела `/stati` хранятся в базе SQLite (`var/prime-auto.db`) и
пишутся в админке `/admin` с помощью нейросети — той же, что в админке vdf.by.

## Как пишется статья

В админке «Написать статью» — три режима:

- **по теме** — тема, главный запрос, нюансы;
- **по ссылке на статью конкурента** — сервер скачивает страницу, нейросеть
  выделяет саму статью и пишет на её основе новую: своя структура, под
  мастерскую, без дословных совпадений;
- **по тексту конкурента** — то же, если сайт не пускает ботов.

Дальше задача идёт на сервере сама, вкладку можно закрыть:

1. **Черновик.** Промпт — `src/lib/article-ai.ts`, правится в «Настройках».
2. **Проверка качества.** Сначала код проверяет формальное: объём, разделы,
   таблица и списки, длина SEO-полей, ссылки на услуги, нет ли цен. Потом
   второй вызов нейросети в роли строгого SEO-редактора получает черновик с
   этими замечаниями, ставит оценку 0–100 и исправляет текст. Правка, которая
   потеряла больше 20% текста, отбрасывается.
3. **Черновик сохраняется** — его уже можно открыть.
4. **Уникальность** (`src/lib/uniqueness.ts`):
   - против текста конкурента — локально, по цепочкам из 5 слов; совпавшие
     абзацы переписываются;
   - против интернета — через text.ru, если задан `TEXTRU_API_KEY`; абзацы с
     найденными фразами переписываются, проверка повторяется.

   Переписываются только проблемные абзацы, не вся статья. Кругов не больше
   `UNIQUE_MAX_ROUNDS` (2). Если порог так и не пройден, статья остаётся
   черновиком с отчётом, где видно, на каких сайтах нашлись совпадения.

Публикует статью человек кнопкой «Опубликовать». Страницы `/stati`, статьи и
`sitemap.xml` обновляются сразу.

У готовой статьи есть кнопки «Проверить и улучшить» (редактор + уникальность)
и «Проверить уникальность».

## Ссылки

Нейросеть получает список страниц сайта (услуги, марки, прайс, статьи) и
ссылок на магазин VDF.BY. После генерации все ссылки сверяются со списком:
выдуманный адрес становится обычным текстом, на магазин остаётся не больше
двух ссылок, на чужие сайты — ни одной. Список магазина правится в «Настройках».

## Вход и настройки

Вход в `/admin` — по одному паролю, без логина. В коде лежит только scrypt-хеш
пароля по умолчанию, открытым текстом его в репозитории нет. Сменить пароль —
в «Настройках» (остальные сессии закрываются). Забытый пароль сбрасывается на
сервере:

```bash
cd /var/www/prime-auto
npm run admin                  # спросит новый пароль
npm run admin -- --default     # вернуть пароль по умолчанию
```

Всё, что касается нейросети и проверок, правится в «Настройках» и действует
сразу, без перезапуска: API-ключ, адрес API, модели (основные и для статей),
прокси, температура автора и редактора, лимит токенов, таймауты, ключ text.ru,
порог уникальности, число кругов переписывания, каталог кеша nginx. Список
полей — `src/lib/config.ts`.

Ключи хранятся в базе и в браузер целиком не отдаются — только последние
четыре символа. Если поле в админке пустое, действует переменная с тем же
именем из `.env` (`AI_API_KEY`, `AI_MODEL`, `AI_PROXY`, `TEXTRU_API_KEY`…),
а если нет и её — значение по умолчанию.

## Разовая настройка на сервере

### 1. Настройки

Зайти в `/admin` → «Настройки» и указать API-ключ OpenRouter и прокси —
те же, что у vdf.by (прокси: `http://127.0.0.1:25345`, pm2-процесс
`vdf-ai-proxy`). По желанию — ключ text.ru и `/var/cache/nginx` в поле
«Каталог кеша nginx», чтобы новая статья появлялась сразу, а не когда истечёт
кеш nginx. Нажать «Проверить связь с нейросетью».

### 2. Пароль

Пароль уже задан. При необходимости меняется в «Настройках» → «Пароль входа».

### 3. nginx: админку не кешировать

Next отдаёт для `/admin` `Cache-Control: private, no-store` и
`X-Accel-Expires: 0`, и этого достаточно при обычных настройках. Если в
конфиге есть `proxy_ignore_headers`, добавьте явное исключение в `server {}`
перед `location /`:

```nginx
location /admin {
    proxy_pass http://prime_auto;
    proxy_http_version 1.1;
    proxy_set_header Host              $host;
    proxy_set_header X-Real-IP         $remote_addr;
    proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_cache off;
}
```

### 4. Деплой

Как обычно, `./scripts/deploy.sh`. База лежит в `var/` рядом с кодом:
`git pull` её не трогает, оба цвета blue-green видят одну и ту же базу.
Старые 6 статей при первом запуске сами переносятся из
`src/constants/articles.ts` в базу.

Задача, которая шла во время деплоя, обрывается: через три минуты она
получит статус «прервалась», запустите её ещё раз.

### Бэкап

Вся база — один файл. Копировать на ходу безопаснее так:

```bash
sqlite3 /var/www/prime-auto/var/prime-auto.db ".backup '/root/backup/prime-auto-$(date +%F).db'"
```

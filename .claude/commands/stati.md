description: Довести до публикации непроверенные черновики статей (текст, обложки Leonardo, картинки) и поставить их в очередь публикации
---

Продолжи расширение блога prime-auto.by по плану `docs/content-expansion.md`. Пользователь запускает эту
команду без пояснений — всё нужное ниже. Работай сам до конца, вопросы задавай только если что-то сломалось.

## Что уже есть

- Черновики статей пишет нейросеть на сервере (очередь в админке). Все черновики — `python art.py list`
  в `tools/articles` (поле `reviewed` — проверена ли).
- Проверенные статьи сами публикуются по одной в день в 9:00 по Минску из очереди публикации
  (`src/lib/publish-schedule.ts`). Ставит в очередь `python art.py sync-queue`.
- Инструкция проверки, факты, цены, требования к картинкам — `tools/articles/REVIEW.md`. Прочитай её целиком.
- Инструменты (`tools/articles`, запускать с `PYTHONIOENCODING=utf-8`): `art.py` (list/get/dump/put/upload/audit/
  factcheck/published/photos/sync-queue), `auto.py` (lint — поиск типичных ошибок кодом, build — правки по плану,
  картинки и запись), `cover2.py` (обложка: Leonardo + заголовок + логотип), `leo.py` (иллюстрация).
  Ключ Leonardo — `~/Desktop/leonardo.txt`, иначе берётся из «Настроек» админки на сервере.
  SSH-ключ сервера — `~/.ssh/vdf_deploy` (Windows) или `~/.ssh/vdf_home` (Mac), art.py выбирает сам.

## Порядок (дешёвый: Claude не читает статьи целиком, кроме выборочной проверки)

1. `cd tools/articles && PYTHONIOENCODING=utf-8 python3 art.py list` — возьми черновики с `"reviewed": false`.
   Если их нет — проверь, не осталось ли тем без статей в плане; если всё сделано — так и скажи.
2. Балансы до старта: Leonardo — `python3 -c "import leo,json;print(json.dumps(leo.call('GET','/me')))"`
   (apiPaidTokens; на статью уходит ~30–40 токенов: обложка + одна иллюстрация). Не хватает — скажи пользователю.
3. Проверка по фактам на сервере (нейросеть-редактор с «Фактами» в задании, ~$0.01 за статью):
   `python3 art.py factcheck <id,id,…>` — для всех черновиков с `"factcheck": null`. Сервер берёт по две;
   жди, пока у всех `factcheck` станет `done` (`art.py list`, раз в несколько минут). `error` — поставь ещё раз
   или оставь на ручную проверку по REVIEW.md.
4. `python3 auto.py lint <id,id,…>` пачками по 10 — по каждой статье: запрос, нюансы, аннотация, разделы и
   найденные места с цитатами. Целиком статьи не читай.
5. Напиши `$TEMP/prime-articles/plan-<n>.json` (формат — в начале auto.py): правки `replace` только по
   замечаниям lint (цитата точно из вывода; выдумку — удалить или заменить фактом из REVIEW.md), блок `how` с
   ценой из «Фактов» REVIEW.md, обложка (scene/title/accent + одно из chips/compare/badge/warning; layout и
   стиль чередуются сами), `image` или своё `photo` (`art.py photos`, если машина названа в нюансах).
   Сомнительное, что lint не может решить заменой, — не правь вслепую: `art.py get <id>` и смотри место.
   Редактор-нейросеть любит вставлять «Факты» не к месту (разделы про гарантию, техосмотр, ДХО, проводку,
   абзац про матрицу и ксенон) — такое убирай заменой на "". Лишние ссылки build снимает сам (trim_links: сначала пути из нюансов, дубли и общие разделы — долой); в replace их не пиши.
   Обложка: compare — это пара ✓/✕, только для «норма / поломка» (не для «2,5 / 3», «город / трасса» — там chips).
   Заголовок обложки — 2–3 слова, иначе плашки наезжают на логотип. Неудачную обложку пересобирай на том же фоне
   (spec "bg": a<id>/auto-cover-bg.png) — Leonardo не тратится.
   Наши работы: редактор дописывает к кейсам подробности («владелец был уверен…», «поменяли только секцию»,
   «частая проблема модели») — выпиши предложения с нашими машинами и оставь только то, что есть в нюансах.
   Холостой прогон плана: `python3 auto.py check plan-<n>.json`; рискованные места без чтения статьи — `auto.py scan`.
   Перед build прогони план вхолостую: все цитаты найдены, lint после правок чистый.
6. `python3 auto.py build plan-<n>.json` — правки, картинки, заливка, запись. «НЕ записана» — исправь план
   (обычно цитата не совпала) и запусти build снова: готовые картинки не генерируются заново.
7. `python3 art.py audit <все проверенные id>` — ноль проблем. Выборочно (1 из 10) открой обложки глазами
   (webp → png через PIL), иллюстрации — все (Leonardo часто рисует сварку металла с искрами, мишени с цифрами,
   свет не от фар; пятно света с границей на стене у него не выходит — не заказывай). Неудачную иллюстрацию — перегенерируй `leo.generate` и подмени в body через dump/put.
8. Сам прочитай 2–3 статьи целиком (`art.py get`): факты сверены, нет выдумок, вставки на месте.
9. `python3 art.py sync-queue` — проверенные встают в очередь публикации (по возрастанию id).
10. Обнови «Статус» в `docs/content-expansion.md`, закоммить и запушь (деплой не нужен — статьи и очередь в базе).
11. Отчёт: сколько проверено, главные исправления по фактам, очередь публикации и на сколько дней её хватит,
    сомнения, которые стоит подтвердить у мастерской.

Помощников (Agent) не запускай — дешёвый процесс укладывается в один разговор.

Ничего не публикуй вручную — публикует расписание. Статьи, которые уже не черновики, не трогай.
